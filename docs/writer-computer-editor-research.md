# Writer Computer editor research

## Scope and snapshot

This note audits only Writer Computer's Markdown editing surface. It does not evaluate its sidebar, tabs, workspace browser, command palette, or product direction except where editor lifecycle or persistence directly affects typing.

The source snapshot is the `master` branch at commit [`eef84557429ee1897c4c0b9eeec39af80cfe199e`](https://github.com/joelbqz/writer-computer/commit/eef84557429ee1897c4c0b9eeec39af80cfe199e), committed on 2026-07-20. The repository was read as untrusted source; none of its scripts or instructions were executed.

## Bottom line

Writer is ahead less because it supports more Markdown and more because it treats Live Preview as an interaction system. Its implementation explicitly handles syntax-tree progression, selection-triggered reflow, pointer-drag stability, invisible-source hit testing, list-prefix cursor geometry, widget height changes, focus, search scrolling, per-file undo state, and cursor/scroll restoration. Those are the parts worth learning from. The full editor assembly is visible in one extension list, while the reusable hide/fold machinery is kept in a local `prosemark-core` layer. [Editor extension assembly](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L534-L697) · [ProseMark setup](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/basicSetup.ts#L29-L67)

It is not a clean Obsidian Live Preview reference implementation. Several elements never reveal their literal source in place; heading markers are moved into the margin and made a forbidden caret zone; rendered links navigate on an ordinary click; wiki-link reveal uses a contained-selection test rather than a true overlap test; Mermaid source never unfolds through the main editor; formatting exists in two implementations; and the unit suite does not mount a real `EditorView` to exercise browser focus, hit-testing, or pointer geometry. Those differences matter if Calmd's target contract is “syntax appears only when the cursor or selection touches the corresponding word or line.” [List source-backed rendering](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/list/index.ts#L27-L63) · [Heading no-go zones](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/heading-decorations.ts#L18-L23) · [Always-rendered Mermaid](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/mermaid-decorations.ts#L176-L198)

## Architecture

Writer constructs `EditorView` directly in a React callback ref. CodeMirror owns the live document; a view update listener copies changed documents and the main cursor offset into an imperative editor-store API. File changes and external reloads are swapped into the existing view with a transaction excluded from undo history, rather than rebuilding the view. On a file-path change, a `Compartment` is removed and re-added to reset per-file undo history without flashing undecorated Markdown. [View construction and restoration](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L728-L789) · [In-place swap and history reset](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L791-L858) · [Update listener](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L656-L668)

The editor language is CodeMirror Markdown configured with Lezer GFM, language data for fenced-code highlighting, local syntax extensions, and a custom HTML-block parser. The local syntax extensions add YAML frontmatter, links with bare-space destinations, nested-link handling, escapes, emoji shortcodes, typographic dashes, and `$…$`/`$$…$$` math. [Language configuration](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L539-L543) · [Local Markdown extension registry](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/markdown/index.ts#L1-L28)

The snapshot resolves CodeMirror view `^6.40.0`, state `^6.6.0`, Markdown `^6.5.0`, and Lezer Markdown `^1.6.1`; its renderers include KaTeX, DOMPurify, Beautiful Mermaid, and node-emoji. Pinning this matters because CodeMirror decoration, measurement, and parser behavior are implementation dependencies of the techniques below. [Dependency catalog](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/pnpm-workspace.yaml#L7-L44)

The Live Preview engine has two reusable registries:

- `hidableNodeFacet` describes syntax nodes whose delimiters should disappear while inactive. The shared field walks the Lezer tree, skips hiding whenever any selection range inclusively touches the configured hide zone, and otherwise emits mark or replace decorations for the syntax tokens. It rebuilds on document, selection, or committed syntax-tree changes. [Hide field and policy interface](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/hide/core.ts#L35-L173) · [Inclusive overlap predicate](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/utils.ts#L50-L61)
- `foldableSyntaxFacet` describes syntax nodes that become replacement widgets while inactive and source while selected. It supports custom unfold zones, persistent decorations during unfold, and shared click-to-range-select behavior for rendered widgets. [Fold field and policy interface](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/fold/core.ts#L17-L123)

This split is useful: delimiter hiding and semantic block replacement have different geometry, navigation, and failure modes, even though both are selection-sensitive.

## Strong ideas to reuse

### 1. Make reveal scope an explicit policy

The strongest abstraction is not “hide all marks on inactive lines.” It is a per-construct policy with a parsed node, tokens to hide, an activation zone, a hiding method, and optional inactive/active decorations. That supports word-level escape reveal, node-level emphasis reveal, line-like heading reveal, source-preserving quote/fence hiding, and fully rendered blocks without one fragile regex pass. [Policy type](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/hide/core.ts#L147-L173) · [Default policies](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/hide/index.ts#L22-L99)

Calmd should define its target contract before adding more constructs: whether each feature reveals by exact syntax node, semantic word, whole line, or whole block; whether non-empty selections activate on overlap; and whether the inactive form preserves width or is allowed to reflow. A shared policy table makes those decisions inspectable and testable.

### 2. Freeze Live Preview shape during pointer drag

If decorations rebuild on every drag-selection mousemove, hidden tokens appear and disappear under the pointer, changing line width and invalidating the drag target. Writer snapshots selection on primary `pointerdown`, freezes hide/fold recomputation, maps the snapshot through any document edits, and unfreezes with a final selection transaction on `pointerup`, `pointercancel`, or blur. [Drag-freeze contract and state](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/drag-selection-gate.ts#L12-L87) · [DOM lifecycle](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/drag-selection-gate.ts#L146-L199)

This is high-value even if Calmd never renders tables, math, or diagrams. Inline delimiter reflow alone can make selection feel broken.

### 3. Treat invisible syntax as an input-geometry problem

Writer documents and encodes the fact that `font-size: 0` syntax spans can destabilize `coordsAtPos` and CodeMirror's drawn selection. It removes emphasis/strikethrough markers from the DOM, keeps blockquote/fence width with opacity, gives list prefixes measurable source-backed spans, adds atomic ranges where caret motion must skip hidden source, and clamps illegal collapsed-caret positions. [Hide mechanisms](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/hide/core.ts#L8-L33) · [List selection guard](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/list/index.ts#L292-L343)

The transferable rule is to choose hiding by geometry:

- `Decoration.replace` for delimiters that should occupy no width.
- Transparent marks when layout width must remain stable.
- Source-backed styled marks for clickable/atomic prefixes where normal DOM hit boxes are valuable.
- Block widgets only when the semantic inactive form genuinely replaces the source.

### 4. Give lists a complete editing contract

Writer's list work covers more than appearance: marker/body click zones, allowed caret boundaries, left/right traversal, Enter continuation and exit, task reset on continuation, Backspace behavior at marker/body boundaries, structured Tab/Shift-Tab nesting, multi-line selection indentation, and checkbox toggling on click rather than `mousedown`. [Caret and pointer behavior](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/list/index.ts#L309-L543) · [Enter, Backspace, and checkbox behavior](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/list/index.ts#L621-L770)

This is the clearest example of why visual parity is insufficient. A list can look rendered while selection, deletion, indentation, and continuation still feel like a source editor fighting its own decorations.

### 5. Keep syntax-tree decoration coverage caught up with the viewport

Lezer parses incrementally, while hide/fold/list fields rebuild from the committed syntax tree. Writer explicitly forces parsing slightly beyond the viewport during scroll and schedules a bounded full-document parse during idle time so newly visible content does not temporarily fall back to raw paragraphs and markers. [Viewport parse plugin](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L184-L236) · [Repository editor note](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/docs/editor.md#L140-L149)

This mechanism should be adopted only after reproducing the same long-document failure in Calmd; it is a targeted solution with explicit budgets, not a reason to synchronously parse every document on every edit.

### 6. Preserve editor continuity across document changes

Writer stores cursor and outer-scroll offsets per open file, restores them on mount and tab switch, focuses a pane when it becomes visible, keeps the same `EditorView` during document swaps, and resets undo history per file. These choices prevent tabs from feeling like newly mounted textareas. [Cursor, scroll, focus restoration](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L130-L181) · [Per-file lifecycle](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L772-L857)

Its custom search scroll handler also uses CodeMirror's document layout model rather than DOM coordinates, because off-viewport positions may not have rendered rectangles. That is a useful precedent whenever an app-level container, fade, or overlay owns scrolling. [Search scroll handler](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L562-L602) · [Repository scroll guidance](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/docs/editor.md#L5-L44)

### 7. Sequence saves per document

Writer's autosave controller is per path, throttles writes to at most once per second, permits only one in-flight write, compares the just-written snapshot with the latest editor state, and schedules a follow-up save if newer edits arrived. This prevents a slow earlier write from marking a newer buffer clean. [Save controller](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/save.ts#L35-L103) · [In-flight sequencing](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/save.ts#L129-L168) · [Regression test](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/tests/save.test.ts#L34-L105)

## Limitations and ideas not to copy blindly

### It is not one consistent Live Preview contract

The generic hide/fold layers activate on inclusive overlap, wiki links activate only when a range is fully contained, list source prefixes never reveal, heading source is displaced into the margin and made non-enterable, and Mermaid never returns to main-editor source. These are deliberate local behaviors, but together they do not implement one Obsidian-like rule. [Generic overlap](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/lib/prosemark-core/utils.ts#L50-L61) · [Wiki contained-range check](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/wiki-link-extension.ts#L194-L222) · [Mermaid replacement](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/mermaid-decorations.ts#L176-L198)

For Calmd, a simpler consistent contract is preferable: inline syntax reveals when any selection overlaps its semantic node; line prefixes reveal when any selection endpoint is on the line; non-empty selections spanning a construct reveal it; and pointer drag freezes the pre-drag rendering until release.

### Heading polish comes with unusual source semantics

Writer positions ATX hashes absolutely to the left of the text, forces their font size back from the generic hidden-token rule, intercepts margin clicks, clamps every selection endpoint out of the marker range, and adds special ArrowLeft behavior to escape that no-go zone. This solves alignment and coordinate bugs, but it is much more invasive than showing the literal prefix in its normal position on the active line. [Heading decoration and click handler](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/heading-decorations.ts#L104-L136) · [Guard and escape keymap](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/heading-decorations.ts#L137-L261) · [Theme rationale](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/prosemark-theme.css#L183-L260)

Calmd should not take this unless flush-left active heading text is a firm requirement and ordinary inline prefix reveal demonstrably feels worse.

### Link navigation conflicts with direct editing

Both Markdown links and wiki links claim an ordinary pointer press so CodeMirror cannot move the caret into the folded link, then navigate on release. That keeps rendered links stable while clicking, but it differs from Obsidian's modifier-to-follow model and makes mouse-first source editing less discoverable. [Markdown link handler](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L401-L449) · [Wiki-link handler](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/wiki-link-extension.ts#L313-L373)

Calmd's modifier-click navigation is better aligned with the requested editing contract; the transferable part is preventing a claimed navigation click from first unfurling and moving the caret, not removing the modifier.

### Formatting has two competing implementations

The vendored setup registers bold, italic, link, and strikethrough shortcuts, while the app adds a second, higher-precedence formatting extension for the same chords plus more commands. The two implementations differ: for example, the core italic command writes underscores and handles outermost parsed wrappers, while the app command writes asterisks and wraps the word under a collapsed caret. The reusable lesson is to keep one command implementation per semantic action and share it between keyboard shortcuts, menus, and context menus.

### The typing path copies and re-derives the whole document

Every CodeMirror document change calls `update.state.doc.toString()`. The store then infers the title and recomputes document statistics by normalizing and scanning the full string before scheduling autosave. The generic hide and fold fields also walk the committed syntax tree whenever the document or selection changes. This is straightforward, but it puts multiple document-scale operations on the edit/selection path and can become visible in long notes; the source does not show a long-document typing benchmark guarding it. ### External reload is not conflict-safe

When an open file changes and Writer does not consider its own save in flight, the watcher cancels a pending save, reads disk, and reloads whenever disk content differs from the last saved snapshot. `reloadFromDisk` then replaces the in-memory content and clears dirty state without a revision comparison or user-visible conflict branch. The repository's own watcher investigation warns that delayed self-write echoes can overwrite keystrokes. [Watcher reload path](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/hooks/use-file-watcher.ts#L16-L36) · [Reload state mutation](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/stores/editor-store.ts#L1163-L1186) · [Repository risk analysis](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/SPECs/reveal-in-sidebar-and-external-watcher-spec.md#L45-L65)

This is specifically not an improvement for Calmd's conflict-safe session and persistence seam.

### Asynchronous image paste does not map its insertion point

Writer waits for the pasted image to be persisted and then reads the editor's current main cursor to insert the generated Markdown. If the user types or moves the caret while the file operation is pending, the image can be inserted somewhere other than the original paste location. [Image-paste flow](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/src/components/editor-area/use-prosemark-editor.ts#L238-L253)

Calmd should capture the original selection range and map it through subsequent CodeMirror transactions, using the same principle already applied to asynchronous wiki-link navigation.

### Browser interaction coverage is the main test gap

Writer has strong state-level tests for list commands and geometry, drag-freeze state transitions, formatting commands, math/table fold state, heading clamps, image height caching, and autosave sequencing. [List tests](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/tests/list-extension.test.ts#L70-L535) · [Drag tests](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/tests/drag-selection-gate.test.ts#L37-L90) · [Table tests](https://github.com/joelbqz/writer-computer/blob/eef84557429ee1897c4c0b9eeec39af80cfe199e/apps/desktop/tests/table-decorations.test.ts#L66-L190)

However, the editor-focused unit tests in the snapshot operate on `EditorState`, exported helpers, widgets, and source/style objects; none mounts `new EditorView`. For Calmd, the minimum high-value integration matrix is:

1. Click before, on, and after hidden delimiters and assert the resulting document position.
2. Drag across inactive bold/italic/code/link syntax in both directions and assert stable selection text and geometry.
3. Shift-select across multiple decorated nodes and confirm every overlapped node reveals after release.
4. Exercise ArrowLeft/ArrowRight, Home/End, Backspace, Delete, Enter, Tab, and Shift-Tab at every hidden-prefix boundary.
5. Scroll a long note into an initially unparsed region and assert decorations are already present.
6. Switch notes and externally reload while checking cursor, scroll, focus, undo isolation, and conflict behavior.

## Recommended adoption order for Calmd

1. **Write the Live Preview activation contract first.** Use one shared inclusive-overlap helper for inline nodes and an explicit line/block policy for prefixes. Include multiple selections and drag-finalization semantics.
2. **Stabilize pointer selection before adding more rendered syntax.** Add a drag-freeze field and browser integration tests around the current formatting and wiki-link decorators.
3. **Audit geometry construct by construct.** Replace zero-font hiding where it creates collapsed DOM boxes; use opacity only where preserving width is intentional; define atomic ranges only for source that should truly be skipped.
4. **Deepen list and blockquote input behavior.** Reuse Writer's boundary-oriented acceptance matrix, but retain Calmd's desired source reveal instead of permanently rendered list prefixes.
5. **Add long-note decoration and typing measurements.** Only then decide whether viewport parse forcing, cached widget heights, or incremental derived metadata are necessary.
6. **Preserve Calmd's conflict-safe persistence design.** Writer's sequential autosave snapshot check is useful, but its external reload behavior is not.

The highest-leverage comparison is therefore not “which Markdown features does Writer render?” It is “does every decoration have a specified activation zone, geometry strategy, pointer-drag behavior, keyboard boundary behavior, persistence interaction, and browser-level regression test?” That is the editor-quality bar Writer's best code points toward, even where its own implementation does not yet meet it consistently.
