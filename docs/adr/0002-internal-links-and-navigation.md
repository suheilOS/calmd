# Internal links, navigation, backlinks, and coordinated rename

Calmd supports top-level wiki links in the forms `[[target]]` and `[[target|display text]]`. Targets identify Markdown filename stems case-insensitively; a trailing `.md` is accepted and omitted when Calmd writes a link. Paths, headings, blocks, embeds, nested links, multiline links, and links in code are not supported. Filename identity and visible title remain separate.

Modifier-clicking a link first flushes the source note. Rust then resolves the target authoritatively by enumerating Markdown filenames and reading only a unique match, rejects ambiguous case-folded matches, or creates a missing note. If filename sanitization or collision handling changes the target, the clicked occurrence is mapped through concurrent CodeMirror transactions, revalidated, rewritten canonically, and flushed before navigation.

Navigation uses application-owned history with a current-position cursor so asynchronous saves and conflicts can veto transitions. It preserves composer thoughts, supports note-to-note Back and Forward traversal, keeps Home reversible by adding a blank composer entry, avoids duplicate self-navigation, truncates forward history after a new destination opens, and rewrites historical keys after an internal rename.

Backlinks are derived state in schema version 4 of the rebuildable SQLite index. Outgoing links are stored by normalized filename identity. Backlink resolution requires exactly one matching target, so externally-created case ambiguities resolve to neither note. Foreign keys are enabled on every connection. The popover fetches backlinks and title-based unlinked mentions only when opened. Backlinks return each source note once; unlinked mentions also exclude supported wiki links and Markdown code before returning one bounded occurrence per source note.

Ctrl-hover on Linux/Windows and Cmd-hover on macOS provides one transient preview for inline wiki links and backlink entries. Preview resolution reads Markdown through dedicated vault commands, returns no result for missing or ambiguous targets, and never creates notes, updates the index, flushes drafts, rewrites links, or enters navigation history. Responses are bounded to 4,000 Unicode scalar values before IPC. A self-preview substitutes the in-memory draft after Rust resolves its authoritative key. Rendering is non-modal, safe Markdown with HTML, images, and navigation inside the preview disabled.

Internal rename scans Markdown rather than relying on the index, rewrites incoming links and self-links, and installs all changed files through the vault-local `.calmd-operation.json` recovery journal. A pre-commit interruption restores backups; a post-commit interruption preserves installed files and removes recovery artifacts. Malformed recovery state blocks vault mutation rather than guessing. Successful operations remove the journal and reconcile derived state afterward.

The current design intentionally leaves filesystem watching, nested folders, external browser history, and persisted navigation or editor-view history out of scope. Cursor, selection, and scroll positions are restored only from a bounded in-memory cache during the current app run. Permanent, conflict-safe note deletion removes the deleted key from application history but deliberately preserves links in other notes and all attachments. Retrieval remains literal and is provided by the rebuildable SQLite/FTS5 index. Semantic retrieval was considered, but literal SQLite/FTS5 retrieval is effective, predictable, and lightweight for the intended workflow and better aligned with Calmd's minimal product philosophy. It is outside Calmd's product direction and is not planned unless usage evidence shows repeated retrieval failures caused by differences in wording.
